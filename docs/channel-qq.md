# QQ Bot：atlas 的 QQ 接入

> **状态**：设计规格，**未实现**（飞书 P0 已先行落地，见 [`channel-feishu.md`](channel-feishu.md)）；本文仍是 QQ 适配器的实现依据与验收清单。架构与选型见 [`channels.md`](channels.md)。

atlas 可以作为一个 QQ 机器人运行（QQ 开放平台官方 Bot API v2）：私聊它、在群里 @ 它。QQ 平台的被动回复时效与主动消息频控会直接塑造这里的交互形态——先读第 5 节的限制表，再看行为设计。

## 1. 工作原理

```
QQ 开放平台
   │  ① access_token（7200s，过期前 60s 刷新）
   │  ② WebSocket 网关（wss://api.sgroup.qq.com/websocket）
   │     op 10 Hello → op 2 Identify / op 6 Resume → op 0 Dispatch，op 1 心跳
   ▼
atlas-gateway 进程
   ├─ 事件去重（message_id）+ 准入（白名单 / @ 门控）
   ├─ 会话绑定：聊天 → atlas 会话文件
   ├─ App.Ask(ctx, prompt, emit)
   └─ 出站 REST /v2/{users|groups}/{id}/messages
        被动回复带 msg_id + 自增 msg_seq；主动消息受频控
```

与飞书的关键差异：QQ 群消息**不支持流式**，也没有消息编辑 API——回答只能整条发。

## 2. 准备工作

1. 在 [QQ 开放平台](https://q.qq.com) 注册并创建机器人应用；个人主体可以创建。
2. 拿到 **AppID** 与 **AppSecret**（客户端密钥）。
3. 功能配置里开启「单聊」和/或「群聊」场景。
4. 群聊：把机器人拉进群。测试期建议用小号/测试群；沙箱与测试号的现行规则以平台控制台为准（⚠ 联调时复核，平台的沙箱域名与测试账号规则改过几次）。
5. 注意默认只收到 **@ 机器人** 的群消息（`GROUP_AT_MESSAGE_CREATE`）；要收群里全部消息需要另行申请「群消息」权限（`GROUP_MESSAGE_CREATE`），atlas v1 按 @ 语义设计，不申请全量。

## 3. 配置 atlas

`atlas.json`：

```json
{
  "channels": {
    "qq": {
      "appId": "xxx",
      "clientSecret": "env:ATLAS_QQ_CLIENT_SECRET",
      "dmPolicy": "pairing",
      "allowedUsers": [],
      "groupPolicy": "allowlist",
      "groups": [],
      "admins": [],
      "cwd": "/Users/crane/work"
    }
  }
}
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `appId` / `clientSecret` | 必填 | 开放平台凭据；secret 支持 `"env:VAR"` 引用 |
| `dmPolicy` | `pairing` | `pairing` / `allowlist` / `open` / `disabled`；配对码回复在私聊里完成 |
| `allowedUsers` | `[]` | 用户的 OpenID 白名单 |
| `groupPolicy` | `allowlist` | `allowlist` / `open` / `disabled` |
| `groups` | `[]` | 群 OpenID 白名单 |
| `admins` | `[]` | 管理员 OpenID |
| `cwd` | — | 该渠道新会话的工作目录 |

环境变量：`ATLAS_QQ_APP_ID` / `ATLAS_QQ_CLIENT_SECRET` 覆盖配置文件。

身份模型：QQ 对机器人暴露的是 **OpenID**（对单个机器人稳定，不是 QQ 号）。白名单、`admins` 里填的都是 OpenID；配对流程会把"发消息的人"和 OpenID 关联起来，不需要手工收集。

## 4. 启动

```bash
atlas-gateway            # 与飞书同一个进程；channels.json 里配了哪个平台就起哪个
```

## 5. 硬限制，以及它们如何塑造行为

这些是平台规则（官方 API 文档），不是 atlas 的取舍：

| 限制 | 数值 | 对 atlas 的影响 |
|---|---|---|
| 被动回复时效 | `msg_id` 5 分钟内有效，同一条消息**最多回 5 次**（超限错误 `40034128`） | 回答必须在 5 分钟内发完，且分片数 ≤ 5 |
| 主动消息频控 | 认证 60 qpm / 未认证 30 qpm；单关系 20 qpm；单群每天 1000 条 | 超过被动窗口的回答走主动消息，计入配额 |
| 去重 | 相同 `msg_id + msg_seq` 重复发送被拒（`40054005`） | 每次回复自增 `msg_seq` |
| 长度 | 超长被拒（`40054007`） | 按平台上限分片 |
| URL | 部分主体不允许消息携带 URL（`40054010`，⚠ 联调复核适用条件） | 出站文本做 URL 检测，被拒时把链接改写为"见文件/附后" |
| Markdown | 需要单独申请权限（`40034127` 无模板权限） | 未开通时一律降级纯文本 |
| 群消息流式 | 不支持 | 不能边写边说 |

**atlas 的回复策略**（把这些限制变成确定的行为）：

1. 收到消息 → 立即发一条**回执**："收到，正在处理…"（占第 1 次被动回复；同时是 QQ 上的 typing 等价物——QQ 私聊支持"正在输入"状态，群聊没有，v1 统一用回执消息，行为一致）。
2. 回答产生 → 作为第 2 次被动回复发出（引用/分段尽量少用，一次说完）。
3. 轮末状态并入第 2 条的尾部，不单独占一次回复——5 次的预算很贵。
4. 若一轮超过 5 分钟没跑完：被动窗口已过，剩余结果改走**主动消息**；主动消息发送失败（频控/权限）时，回复"本轮结果已存入会话，稍后私聊我输入 `/status` 查看"。
5. 长回答超过 5 次分片预算：合并压缩发送，结尾注明"已截断，输入 `/new` 或继续追问展开"。
6. 审批问题占 1 次被动回复，答案文本 `y/n/a` 占 1 次——一次需要审批的轮最多消耗 3 次被动回复（回执、审批、结果），仍在 5 次之内。

## 6. 聊天里的行为

**私聊**：直接说话；`pairing` 流程同飞书（首次收到配对码，owner 用 `atlas-gateway approve <code>` 批准）。

**群聊**：必须 @ 机器人，@ 前缀被剥掉。非 @ 消息不处理（QQ 默认也不会推给机器人）。

**会话绑定**：

| 聊天类型 | 会话粒度 |
|---|---|
| 私聊 | 每个用户一个会话 |
| 群聊 | 每个群一个会话 |

QQ 没有话题概念，绑定只有这两类；绑定落盘与解绑规则与飞书一致（`$ATLAS_HOME/channels/bindings.json`）。

**聊天命令**：`/new`、`/stop`、`/status`、`/cwd <路径>`（仅管理员）、`/help`。语义与飞书相同；差异是 `/stop` 在 QQ 上无法撤回已经发出的回执消息，中止后已发出去的部分保留。

## 7. 审批

- 审批问题作为一条被动回复发出：工具名 + 要做的事 + `回答 y（允许）/ a（总是允许）/ n（拒绝）`。
- 答案只接受发起者与管理员；群里其他人的回答被忽略。
- 5 分钟超时等于拒绝——与平台的被动窗口一致，不是巧合：审批等待的设计预算就是"在一轮被动窗口内完成"。
- QQ 的内嵌键盘（keyboard）可以做成按钮审批，但需要键盘权限且行为不如文本直接；v1 用文本，按钮列为 P2。
- "总是允许"的会话级记忆与终端一致：只记工具名 + 本会话，换会话失效。

## 8. 媒体

| 方向 | v1 | 说明 |
|---|---|---|
| 入站图片 | 下载 attachments 并进入上下文 | 事件自带 attachments 数组 |
| 入站语音 | 优先用事件自带的 `asr_refer_text`（平台侧转写，免费） | 没有转写字段时提示改用文字 |
| 出站富媒体 | 先 `POST /v2/users/{openid}/files` 或 `/v2/groups/{group_openid}/files` 上传拿 `file_info`，再发 `msg_type=7` | 大文件分片上传参考 hermes 的 `qqbot/chunked_upload.py` |
| 出站文件 | 同上 | — |

## 9. 故障排查

| 现象 | 先查 |
|---|---|
| WS 连上即断，码 `4013` / `4014` | intents 没权限——单聊 + 群聊事件未开通 |
| token 获取成功后立刻断开 | 凭据没问题；检查平台上单聊/群聊场景是否开启、机器人是否已加群 |
| 群里收不到消息 | 是否 @ 了机器人；机器人是否在群里；`groups` 白名单 |
| 回复没到，日志有 `40034128` | 被动窗口超时或次数用尽——检查是否卡在审批等待 |
| 日志有 `40034100` | 主动消息频控——降低分片数，检查单群当日配额 |
| 日志有 `40054005` | `msg_seq` 未自增（实现 bug）或重发 |
| 日志有 `40054010` | 主体不允许 URL；确认适用条件后做出站改写 |
| 日志有 `40034127` | Markdown 权限未开通；确认降级为纯文本的开关已生效 |
| 回答不接上下文 | `/status` 看绑定；`bindings.json` 是否被清过 |

## 10. 安全默认值

- 与飞书同一套默认拒绝：`pairing` 起步，白名单按 OpenID。
- 群里的审批只认发起者与管理员；`y/n/a` 必须是独立一条消息且来自授权者。
- OpenID 不是 QQ 号：日志里出现 OpenID 不等于泄露真实身份，但正文仍然只进 DEBUG。
- token 在内存持有、过期前刷新，不落盘；`clientSecret` 只从环境变量或配置引用读。
