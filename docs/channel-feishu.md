# 飞书 Bot：atlas 的飞书接入

> **状态**：P0 已实现（`channel/` module 的飞书适配器 + `atlas-gateway` 二进制）：文本双向、会话绑定、白名单与配对、@ 门控、文本审批（y/n/a）、⏳/❌ 表情回应、8000 字分片、五条聊天命令。**尚未实现**：卡片按钮审批（P1）、图片与文件上下行（P1）、语音转写、webhook 模式。逻辑由单元测试覆盖；真机验收（真实长连接与收发）需要有飞书应用凭据后按本文走一遍。架构与选型见 [`channels.md`](channels.md)。

atlas 可以作为一个飞书机器人运行：私聊它、在群里 @ 它，消息进入 atlas 的内核处理，回答回到同一个聊天。它在服务器上是一个长连接进程，不需要公网 IP 或域名。

## 1. 工作原理

```
飞书开放平台
   │  WebSocket 长连接（larkws，SDK 内置加密与鉴权）
   ▼
atlas-gateway 进程
   ├─ 事件入队（3 秒内先返回，处理在后台 goroutine）
   ├─ 准入：白名单 / 群策略 / @ 门控 / 去重
   ├─ 会话绑定：聊天 → atlas 会话文件（每聊天一个内核 slot）
   ├─ App.Ask(ctx, prompt, emit)  ← emit 的增量被聚合成分片消息
   └─ 出站：im/v1/messages 发送 / reply，长回答按 8000 字分片
```

消息在 3 秒内先被接收并确认（长连接模式下平台要求 3 秒内处理完，否则重推），真正的回答异步产生后发回聊天。

## 2. 准备工作

在 [飞书开放平台](https://open.feishu.cn/) 上完成一次，全部免费：

1. **创建企业自建应用**。长连接模式只支持自建应用，不支持商店应用。
2. **添加机器人能力**：应用详情 → 添加应用能力 → 机器人。
3. **开通权限**（权限管理 → 开通并批量开通）：

| 权限 | 用途 |
|---|---|
| `im:message` | 消息收发的基础 |
| `im:message.p2p_msg` | 接收用户发给机器人的单聊消息 |
| `im:message.group_at_msg` | 接收群里 @ 机器人的消息 |
| `im:message:send_as_bot` | 以应用身份发消息 |
| `im:chat:readonly` | 读群名（会话标题与上下文用） |
| `im:resource` | 上传/下载消息里的图片与文件 |

   权限名称以开放平台权限面板当时显示的为准，名称随版本调整过；申请后在「批量开通」里确认没有遗漏。
4. **配置事件订阅**：事件与回调 → 事件配置 → 订阅方式选「**使用长连接接收事件**」。保存这一步要求网关已经在线——先在本地跑起 `atlas-gateway`（见第 4 节），再保存。
5. **订阅事件**：必需 `im.message.receive_v1`；可选 `im.message.reaction.created_v1` / `im.message.reaction.deleted_v1`（用户对机器人消息点表情时触发合成事件，P1 用于"继续/取消"）。
6. **发布应用版本**，可用范围先设为只含自己，验证后再扩大。
7. **拿凭据**：凭证与基础信息页的 App ID 与 App Secret。

最后把机器人拉进测试群（群设置 → 群机器人 → 添加），或直接给它发私聊消息。

## 3. 配置 atlas

`atlas.json`：

```json
{
  "channels": {
    "feishu": {
      "appId": "cli_xxx",
      "appSecret": "env:ATLAS_FEISHU_APP_SECRET",
      "mode": "ws",
      "dmPolicy": "pairing",
      "allowedUsers": [],
      "groupPolicy": "allowlist",
      "groups": {},
      "admins": ["ou_owner_xxx"],
      "requireMention": true,
      "allowBots": false,
      "cwd": "/Users/crane/work"
    }
  }
}
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `appId` | 必填 | 开放平台的 App ID |
| `appSecret` | 必填 | 支持 `"env:VAR"` 引用环境变量；明文写进配置文件不推荐 |
| `mode` | `ws` | `ws`（长连接）或 `webhook`。webhook 需要公网可达的 URL、verification token 与 encrypt key——v1 只实现并只读 `ws` |
| `dmPolicy` | `pairing` | 私聊策略：`pairing` / `allowlist` / `open` / `disabled` |
| `allowedUsers` | `[]` | open_id 白名单。空列表 + `pairing` 表示"等配对" |
| `groupPolicy` | `allowlist` | 群策略：`allowlist` / `open` / `admin_only` / `disabled` |
| `groups` | `{}` | 每群覆盖：`{"oc_xxx": {"policy": "open", "requireMention": false}}` |
| `admins` | `[]` | 管理员的 open_id：可回答审批、可用 `/cwd`、不受群白名单限制 |
| `requireMention` | `true` | 群里是否必须 @ 机器人才响应 |
| `allowBots` | `false` | 是否响应其他机器人；保持关闭，防止 bot 互刷 |
| `cwd` | — | 这个渠道新会话的工作目录；不填用 atlas 默认 |

环境变量优先级：`ATLAS_FEISHU_APP_ID` / `ATLAS_FEISHU_APP_SECRET` 覆盖配置文件；`appSecret` 也支持 `"env:VAR"` 引用。Secret 永远不写进日志。运行时状态（配对码、运行时白名单、聊天绑定、去重环）在 `$ATLAS_HOME/channels/` 下。

## 4. 启动

```bash
atlas-gateway                      # 前台运行；channels.json 里配了哪个平台就起哪个
atlas-gateway --config /path/config.json   # 内核用的 atlas 配置（默认 atlas home 下的）
```

运行要求：机器能访问公网即可（长连接是出站的 WebSocket，不做入站监听）。日志里连接成功会打出"长连接已就绪"；事件订阅保存失败时先看这一步是否在线。

## 5. 聊天里的行为

**私聊**：直接说话即可。`dmPolicy: "pairing"` 时，白名单为空的首次私聊会收到一个配对码，owner 在网关所在机器执行 `atlas-gateway approve <code>` 后该用户被记入运行时白名单——这是"默认拒绝"的另一半：没批准之前，消息只会收到配对指引，不会进入内核。配对码 30 分钟过期；approve 立即生效，不需要重启网关。

**群聊**：默认必须 @ 机器人（`requireMention: true`），@ 的部分会被从正文剥掉。某个群想免 @，在 `groups` 里覆盖。

**话题**：飞书话题组的话题（`thread_id`）各自是独立会话——话题是天然的并行分支，不与群主聊天共享上下文。

**会话绑定**：

| 聊天类型 | 会话粒度 |
|---|---|
| 私聊 | 每个用户一个会话 |
| 普通群聊 | 每个群一个会话 |
| 话题 | 每个话题一个会话 |

绑定关系落盘在 `$ATLAS_HOME/channels/bindings.json`，第一次说话时创建；删除该条目即解绑，下一条消息开新会话。每个绑定在自己的 worker 里串行执行：同一聊天两条消息不会跑出两个并发内核。

**回复形态**：

- 收到消息先给原消息加一个 `Typing` 表情回应（飞书没有"正在输入"，表情回应是它的 typing 等价物）；回答完成撤掉它，失败改钉 `CrossMark`。
- 回答作为**引用回复**发出（引用你那条提问），长回答按 8000 字分片，只有第一片带引用。
- v1 不做过程刷屏：回答在轮末一次发出，轮尾附一行耗时。
- 回答发送前经过 markdown 降级（粗体/斜体/链接/标题/引用转纯文本，行内代码与围栏代码原样保留）。

**聊天命令**：`/new`（绑定开新会话）、`/stop`（中止正在跑的一轮，已产生的部分回答会发出来）、`/status`（当前会话、模型、上下文占用）、`/cwd <路径>`（仅管理员，改这个绑定的默认工作目录）、`/help`。命令只认发送者为本聊天绑定对应的人（群里即 @ 的那个人）或管理员。

## 6. 审批

atlas 的工具审批在飞书里这样走：

- **已实现（文本版）**：审批以普通消息发出（工具名 + 要做的事），被授权者回答 `y` / `a` / `n`；回答在路由层直接结算，不进聊天队列——轮在跑时入站循环依然空闲。
- **未实现（P1）**：交互卡片按钮（允许 / 总是允许 / 拒绝），点击即答，卡片原地更新状态——这是飞书相对其他平台最大的优势，按钮回调在卡片事件里同步返回，能保证多个客户端看到一致状态。

等待有 5 分钟超时，超时等于拒绝；`/stop` 也会让等待中的审批以拒绝收场。等待期间入站循环不阻塞，其他消息照常排队。

## 8. 限制与边界

- **3 秒窗口**：事件先入队再处理，所以平台的 3 秒重推不会造成重复回答——去重按 `message_id`，同一条消息只处理一次。
- **50 条连接**：每个应用最多 50 个长连接；`atlas-gateway` 单进程只建一条。
- **集群模式**：同一条事件只投给随机一个连接。多机部署同一个飞书应用时不会重复回答，但也意味着不能靠多实例分摊负载。
- **Markdown 降级**：飞书富文本与卡片都支持比 CommonMark 更窄的语法。atlas 的回答按 markdown 生成，发送前降级为飞书文本支持的子集（粗体、斜体、代码、链接），表格转为缩进文本。降级规则实现后要给出对照测试。
- **webhook 模式**：v1 不实现；它是 webhook 签名/解密与公网暴露的组合，等长连接方案稳定后再评估。

## 9. 故障排查

| 现象 | 先查 |
|---|---|
| 收不到任何消息 | 订阅方式是否已切到"长连接"（不是"将事件发送至开发者服务器"）；应用版本是否已发布；权限是否全部开通并生效 |
| 保存订阅方式失败 | 网关是否在线——长连接模式下保存要求有一条活跃连接 |
| 私聊有回音、群里没有 | `im:message.group_at_msg` 权限；群里是否 @ 了机器人；`groups` 里该群的策略 |
| 能收不能发 | `im:message:send_as_bot` 权限；机器人是否还在群里 |
| 回答不接上下文 | `bindings.json` 里该聊天的绑定是否被删过；`/status` 看当前会话 |
| 审批一直等 | 发回答的人是否是发起者或管理员；`y/n/a` 是否单独一条消息 |
| 日志里没有脱敏后的内容 | 这是预期行为；正文与 openid 只进 DEBUG |

## 10. 安全默认值

- 所有渠道默认拒绝：`dmPolicy` 与 `groupPolicy` 的默认值都不放行陌生人。
- 白名单按 open_id 存储；open_id 是应用维度的，换应用后需要重新收集——这是飞书的身份模型决定的，配对流程会替你完成。
- 审批答案只接受发起者与管理员；群里其他人无法替 owner 批准。
- 日志只记录长度、平台 id 与哈希，正文、显示名、手机号一律 DEBUG 以下。
